# ユーザー共通指示

## 応答

- だ・である調で書く
- 断定と推測を混ぜない
  推測の箇所は「推測だが」と明示する
- 質問は「何を決めるか」を一文目に置き、選択肢は名詞で書く
  説明は「選ぶと何が起きるか」だけを書く
- 改行は句点の後にのみ置き、段落の区切りは空行にする
  応答・生成する md・コミットメッセージのすべてに当てる
- 箇条書きの項目の中の文には句点を付けず、文の切れ目は改行だけで示す

## 語彙（`.claude/rules/writing.md` を持つリポジトリでは、そちらが正）

読み手はこのセッションを見ていない、を既定にする。

- 比喩で言えることは直叙で言う
  言い換えが存在する比喩は装飾なので使わない
- 独自用語は、リポジトリが用語集を持つならその語だけ使い、持たないなら使わない
  どちらでも初出で一行定義し、語を一般的でない意味へ転用しない
- 難語は意味の精度を上げるなら使い、装飾なら使わない
- 各文の主語と目的語を名詞で書き、「これ」「例の」「上の議論」「先ほどの方針どおり」で対象を指さない
- 結論は動詞で言い切り、理由は結論の前に置く（「B なので A」）
  言い切った文の末尾へ `——` で補足を継ぎ足さない
- issue・PR・ADR の番号には人間が分かる名前を添える（`#9（検索の絞り込み UI）`）
  同じ番号を続けて指す間は初出だけでよく、コミットのハッシュは対象外
- 残る文章を書く直前に、指示語・比喩・会話を指す語の3種を走査して置き換える
  English text follows the same rules

## セッションのタイトル

取り組む issue が定まったら、`#68 ログイン導線を作る` の形（番号と要約の両方）で付け直す（`set_session_title` を `self` で呼ぶ）。
付け直すのは対象が定まった時点と、途中で対象が変わった時点。issue に紐づかない作業は要約だけにする。

## 検索・列挙

`agent-rg` / `agent-find` を使う。`rg` / `find` の直接実行は避ける。

## コピペ用マークダウンの出力

PR 説明文・Issue 本文・コミットメッセージなど、ユーザーがそのまま貼るマークダウンは、コードフェンスで囲み生のソースのまま出す。

- フェンスは中身の最長バッククォート連より1本多くする
  既定は4本
  言語タグは `markdown`
- フェンス内には貼る内容だけを入れ、分割せず1つのフェンスに収める

## ユーザーが実行するコマンドの出力

ログインシェルは fish。ユーザー自身に実行させるコマンドは fish 構文で出し、フェンスの言語タグも `fish` にする（エージェントが自分の Bash ツールで走らせるコマンドは対象外）。

- ヒアドキュメント（`<<EOF`）が無い
  変数代入は `set VAR value`、環境変数は `set -x VAR value`、コマンド置換は `(cmd)`
- 単一引用符の中で解釈されるエスケープは `\'` と `\\` だけ
- 複数行のスクリプトは貼らせない
  エージェント側でファイルに書き出し、ユーザーの操作は実行1行だけにする
