# ユーザー共通指示

## 応答

- だ・である調で書く。
- 断定と推測を混ぜない。推測の箇所は「推測だが」と明示する。
- 質問は「何を決めるか」を一文目に置く。選択肢は名詞で書き、説明は「選ぶと何が起きるか」だけを書く。

## 語彙と文体（日本語・英語とも）

読み手はこのセッションを見ていない、を既定にする。コメント・コミット・PR・md は、その文と対象のコードだけで意味が取れること。

- 比喩で言えることは直叙で言う。言い換えが存在する比喩は使わない。
- 各文の主語と目的語を名詞で書く。「これ」「例の」「上の議論」で対象を指さない。
- 会話を指す語（「先ほどの方針どおり」「per our discussion」）を残る文章に書かない。内容をその場に書く。
- 結論は動詞で言い切る。含意・反語で結論を代替しない。
- コードのコメントは、他の文書や用語を前提にしない。参照が要るなら要点をコメント内に書く。
- プロジェクトが用語集を持つならその語だけ使う。
  持たないなら独自用語を使わない。
  どちらでも初出で一行定義し、語を一般的でない意味へ転用しない。
- 難語は意味の精度を上げるなら使ってよい。装飾なら使わない。
- 理由は結論の前に置く（「B なので A」）。言い切った文の末尾へ `——` で補足を継ぎ足さない。
- 残る文章を書く直前に、指示語・比喩・会話を指す語の3種を走査して置き換える。

English text follows the same rules: say it literally, name the subject and object with nouns, never refer to the conversation, state the conclusion with a verb, and make every comment understandable from the code alone.

悪例 → 良例:

- `Handled the edge case per our earlier discussion` → `Return an empty list when items is None (previously raised TypeError)`
- `上の方針どおり入口を一本にする` → `入力手段を dispatch-capture の1本に限る`

## 番号・記号で事物を指すとき

issue・PR・ADR の番号には、人間が分かる名前を添える（`#9（検索の絞り込み UI）`）。番号だけで進む文は書き手にしか復元できないため。チャットの応答も対象。

- 同じ番号を続けて指す間は初出だけでよい。
- コミットハッシュはこの限りでない。何のコミットかは次の行の本文が言う。

## セッションのタイトル

取り組む issue が定まったら、`#68 ログイン導線を作る` の形（番号と内容の要約の両方）でセッションタイトルを付け直す（`set_session_title` を `self` で呼ぶ）。番号だけでは一覧から中身を復元できず、要約だけでは同じリポジトリの別セッションと見分けが付かないため。

- 付け直すのは対象が定まった時点と、途中で対象が変わった時点。
- issue に紐づかない作業（調査・設定の調整など）は、内容の要約だけにする。

## 改行

改行は句点の後にのみ置く。文の途中では折り返さない。段落の区切りは空行。応答本文・生成する md・コミットメッセージのすべてに適用する。

## 検索・列挙

`agent-rg` / `agent-find` を使う。`rg` / `find` の直接実行は避ける。

## コピペ用マークダウンの出力

PR 説明文・Issue 本文・コミットメッセージなど、ユーザーがそのまま貼るマークダウンは、レンダリングされると原文が失われる。必ずコードフェンスで囲み、生のソースのまま表示する。

- フェンスは中身の最長バッククォート連より1本多くする。既定は4本。
- 言語タグは `markdown`。
- フェンス内には貼る内容だけを入れる。補足はフェンスの外。
- 分割せず1つのフェンスに収める。

## ユーザーが実行するコマンドの出力

ログインシェルは fish。ユーザー自身に実行させるコマンドは fish 構文で出し、フェンスの言語タグも `fish` にする。エージェントが自分の Bash ツールで走らせるコマンドは対象外。

- ヒアドキュメント（`<<EOF`）が無い。
- 変数代入は `set VAR value`、環境変数は `set -x VAR value`。
- コマンド置換は `(cmd)`。
- 単一引用符の中で解釈されるエスケープは `\'` と `\\` だけ。

複数行のスクリプトは貼らせない。エージェント側でファイルに書き出し、ユーザーの操作は実行1行だけにする。
